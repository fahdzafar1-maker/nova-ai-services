Next.js 15 (App Router, TypeScript) · Tailwind CSS · Framer Motion · Supabase (Postgres + Auth + RLS) · Google Gemini · n8n webhooks.

Public site: Home, Products & Services, Demos (12 interactive demos), About Us, Contact Us, Privacy.
Admin: `/admin/login` → dashboard, leads, inquiries & bookings, order requests, services, demos, analytics, settings.

## 2. Database (Supabase) — already applied

The schema and seed were applied to your project **fahdzafar1-maker's Project** (`euqzbderrfbgawvjdclq`). All tables are prefixed `site_` so they don't touch the existing Skyline `leads` / `n8n_chat_histories` tables.

Files (for a fresh project or the Supabase CLI):
- `supabase/migrations/20261009000001_site_platform.sql` — tables, indexes, constraints, functions, RLS policies
- `supabase/migrations/20261009000002_seed_catalog.sql` — 23 services, 12 demos, admin allow-list (generated by `node --experimental-strip-types scripts/gen-seed.mts`)
- `supabase/manual/hardening.sql` — **run once in the SQL editor**: revokes public API access to private tables/functions (data is already protected by RLS; this also hides them from the API schema) and removes an old helper
- `supabase/manual/maintenance.sql` — purge old rate-limit rows / analytics retention

Security model: RLS on every table. The public (anon) key can only read published services and demos. All public writes go through server routes that validate, rate-limit and then use the service-role key (server-only). Admin pages use the signed-in user's session, so RLS enforces admin access on every query as well.

## 5. Deploy (GitHub `nova-ai-services` → Vercel)

The current site is a single static `index.html`. This project replaces it with a Next.js app:

1. Replace the repository contents with this project (keep the same repo so the domain stays connected). Do **not** commit `.env.local`.
2. Vercel → Project → Settings → **Build & Deployment → Framework Preset: Next.js** (it was "Other" for the static site). Build command `next build`, output: default.
3. Add the environment variables (section 4), then **Redeploy**.
4. Visit `/`, `/demos`, `/contact`, `/admin/login` on the live domain and run the checklist below.

Local development: `npm install` → `npm run dev` → http://localhost:3000. Production check: `npm run build && npm start`.

## 6. n8n integration

Every saved submission triggers one POST to `N8N_WEBHOOK_URL` **after** it is safely stored (the visitor never waits for n8n):

```json
{ "event": "inquiry.created | booking.created | order.created | lead.created",
  "ref": "FAI-INQ-7K2M9Q",
  "data": { "leadRef": "FAI-LEAD-…", "requestRef": "…", "name": "…", "email": "…", "phone": "…", "company": "…", "service": "…", "budget": "…", "message": "…", "source": "form | ai" },
  "sentAt": "ISO date" }
```

Headers: `X-Fahd-Signature` = HMAC-SHA256(raw body, `N8N_WEBHOOK_SECRET`), `Idempotency-Key` = the reference.
In n8n: Webhook (POST, raw body) → Code node that recomputes the HMAC and rejects mismatches → IF on `event` → Slack/Gmail/Sheets/CRM.
Retries: 3 attempts with back-off. Every outcome (sent / failed / skipped) is written to `site_notification_log` and shown in **Admin → Settings**; failures also appear as a warning on the dashboard. If n8n is down or not configured, the submission is still saved.
